Is Bitcoin better understood as a state machine or a database?

Question

Bitcoin is commonly described as a “decentralized database,” but looking at how a full node actually works, that framing feels a bit off.

Blocks form an append-only transaction log. Nodes replay that log to derive the current UTXO set, which Bitcoin Core stores in LevelDB (chainstate/). That’s not really how traditional databases work — it feels closer to event sourcing or a replicated state machine where the ledger state is derived rather than primary.

So which mental model is actually correct?

•   Is the UTXO set the “database “?
•   Or is the block log canonical, with the UTXO set essentially being a cache that could be reconstructed?

Is there anything from early mailing list discussions or Satoshi’s design notes that addresses this directly?

Answer 1

which mental model is actually correct?

Bitcoin is

  • A currency - a unit of measure.
  • A network protocol by which payments can be made.
  • A set of consensus rules.
  • A definition of a transaction journal arising from the rules and protocol.

If you accept the above, wouldn't defining bitcoin as a state machine or as a database or both be either superfluous or secondary at best?

As far as I can see, the Bitcoin network as a whole, does not have a predefined finite set of states which it moves between according to predefined events. So it doesn't look to me like a classical state machine.

The transaction journal called "the blockchain" is an essential part of Bitcoin but it isn't a database in the usual technical sense, The blockchain definition effectively defines only a single unnormalised table and does not define what indexes should exist. It isn't a distributed database in the normal sense and it is both replicated and decentralised. However it is only a database in the broadest sense that you could call any structured collection of data a database. I could call my old diary a database. I don't see the utility of this.

Yes conventional databases and state machines may be useful in implementations but that doesn't mean Bitcoin is those things.

Since the UTXO set can be constructed from the blockchain it is secondary and arguably superfluous - it could be considered merely an artifact of performance optimisation.

Answer 2

I think this is largely a matter of perspective rather than technical accuracy.

Personally, I think of the UTXO set (+ hash of the currently active block) as "the database/state" of the system. Blocks are authenticated "patches" to that database. Bitcoin Core internally produces "undo" files that are used when there is a reorg to revert them and return the state to an earlier block.
